# صوت

تطبيق دردشة صوتية مباشر: يستخدم WebRTC لنقل الصوت بين المشاركين، وNode.js مع Socket.IO لتنسيق الاتصال وتبادل بيانات WebRTC فقط. لا تُرسل الوسائط الصوتية عبر الخادم ولا تُسجّل.

تدعم الواجهة قنوات بأسماء وروابط مستقلة، تنبيهات دخول ومغادرة قابلة للكتم، مؤشر النشاط الصوتي، مزامنة حالة كتم الميكروفون، مشاركة الشاشة مع معاينة وإيقاف المشاركة، ومظهراً فاتحاً أو داكناً. الواجهة متجاوبة مع الهواتف والأجهزة اللوحية، والقناة تدعم حتى 8 مشاركين.

## مشاركة الملفات — 18 حماية وميزة

1. اختيار مستلم بعينه من أعضاء القناة.
2. طلب قبول صريح قبل بدء الإرسال.
3. خيار رفض الطلب وإشعار المرسل.
4. نقل مباشر بين الجهازين عبر WebRTC DataChannel المشفر بـ DTLS.
5. حد أقصى 8 MiB للملف.
6. رفض امتدادات تنفيذية/نشطة شائعة.
7. التحقق من اسم الملف وحجمه ونوعه على الخادم والعميل.
8. تقسيم النقل إلى كتل 64 KiB.
9. قراءة الكتل بشكل غير متزامن لتجنب تجميد واجهة المتصفح.
10. تنظيم ضغط الشبكة قبل إرسال كتل جديدة.
11. إظهار التقدم وحالة النقل للطرفين.
12. إلغاء النقل من أي طرف.
13. التحقق من سلامة المحتوى ببصمة SHA-256.
14. عدم تنزيل الملف تلقائياً بعد استلامه.
15. عدم تمرير محتوى الملف أو تخزينه على الخادم.
16. طلب واحد قيد المراجعة/النقل لكل مستلم.
17. حد للطلبات ووقت انتهاء تلقائي للطلبات والنقل.
18. حصر الطلبات والإشارات في أعضاء القناة والتحقق من الموافقة على الخادم قبل تفاوض نقل الملف.

تدعم الواجهة اختيار الملف أو سحبه وإفلاته في مساحة المشاركة. قائمة الامتدادات الممنوعة ليست فاحصاً للبرمجيات الضارة؛ لا تقبل الملفات إلا ممن تثق به، وافحصها بجهازك قبل فتحها. أسماء الملفات وبياناتها الوصفية وإشارات WebRTC تمر عبر الخادم، أما بايتات الملف فمباشرة بين الجهازين.

يمكن ضبط `MAX_FILE_SIZE` لتقليل الحد الحالي (8 MiB). لا تسمح النسخة الحالية بزيادته عن 8 MiB؛ رفع الحد ينتظر استكمال النقل المتدفق والتحقق منخفض الذاكرة.

## إعدادات الصوت

تتضمن الخيارات اختيار الميكروفون، مرشحاً ترددياً قابلاً للتشغيل والإيقاف لتخفيف الترددات المنخفضة والعالية، رفعاً محدوداً لمستوى الإرسال مع ضاغط ديناميكي لتقليل القصّ، مستوى صوت مستقل للمشاركين، ومقياس مستوى الميكروفون. يمكن تشغيل تقليل الضوضاء وإلغاء الصدى وضبط الكسب التلقائي حسب دعم المتصفح، واستخدام الضغط المطوّل على المسافة للتحدث. معالجة الضوضاء تعتمد على إمكانات المتصفح والعتاد، ولا يوجد مرشح ذكاء اصطناعي مخصص.

تحتاج مشاركة الشاشة إلى متصفح يدعم `getDisplayMedia` وسياق آمن (HTTPS أو localhost)، وقد لا تتوفر على بعض متصفحات الهواتف. بايتات الصوت والفيديو تنتقل مباشرةً بين المشاركين عبر WebRTC.

تُخزَّن مرشحات ICE التي تصل قبل وصف الاتصال مؤقتاً حتى اكتمال التفاوض، ويعيد التطبيق محاولة الاتصال عند انقطاع ICE المؤقت. هذا لا يغني عن إعداد TURN؛ قد يتعذر الاتصال بين بعض الشبكات من دونه.

## التشغيل

يتطلب Node.js 18 أو أحدث.

```bash
npm install
npm start
```

افتح `http://localhost:3000`، أدخل اسمك واسمح باستخدام الميكروفون. يمكنك الانضمام إلى الغرفة الحالية أو إنشاء قناة جديدة باسم تختاره ثم نسخ رابط الدعوة لمشاركته. القنوات وطلبات الملفات مؤقتة في ذاكرة الخادم، ولا تُحفظ بعد إعادة تشغيله أو مغادرة آخر مشارك.

يتوفر فحص صحة الخادم عبر `GET /healthz`، ويعيد حالة JSON بسيطة للاستخدام في مراقبة الخدمة.

## النشر

يجب تقديم التطبيق عبر HTTPS للسماح للمتصفحات باستخدام الميكروفون وWeb Crypto خارج `localhost`. يحتاج الاتصال من شبكات مختلفة إلى STUN، وقد تتطلب بعض الشبكات TURN لضمان الاتصال. لا توجد قاعدة بيانات أو مصادقة؛ رابط الدعوة يعمل كرمز حامل، لذا شاركه مع من تثق بهم. في اتصال P2P قد يتمكن المشاركون من استنتاج معلومات اتصال الشبكة لبعضهم. لا يمكن ضمان خلو أي تطبيق من كل الثغرات؛ اجعل Socket.IO عبر HTTPS، وحدّث الاعتماديات، ولا تعتبر موافقة الاستلام فحصاً للملف.

تُقدَّم إعدادات ICE من `GET /api/ice`. لضبط TURN، عيّن `TURN_URLS` و`TURN_SHARED_SECRET` في بيئة الخادم؛ تُنشأ بيانات اعتماد HMAC مؤقتة ومتوافقة مع مصادقة Coturn REST، وتنتهي صلاحيتها بعد `TURN_CREDENTIAL_TTL_SECONDS`. استخدم ملف `.env.example` كمرجع، واضبط `ALLOWED_ORIGINS` على أصول التطبيق المسموح بها في النشر. لا تضع السر في الواجهة أو المستودع.
